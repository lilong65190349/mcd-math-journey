# 麦麦取经录 · mcd-math-journey

```
[ Python 3.13 ]  [ 纯标准库 · 零第三方依赖 ]  [ 只读 MCP · 不下单 ]  [ 无令牌可离线跑 ]  [ 5 条故事线 ]  [ MIT ]
```

> **题目里的数字都是真的，答案由麦当劳 MCP 真实计算校验。**
>
> 用麦当劳 MCP 的真实菜单、营养、价格、优惠券数据，给小学 3-6 年级自动生成数学应用题，
> 用《西游记》《三国演义》《水浒传》、丝路商队、郑和下西洋**五条故事线**当外壳。
> **故事只是外壳，数学才是主体**——9 个题型模板五条线完全共用。

非麦当劳官方产品，输出仅供参考，餐品信息与价格以麦当劳官方渠道实时结果为准。

---

## 一、项目亮点

1. **数字是真的**：题目里的价格、热量、蛋白质、优惠券门槛，全部来自麦当劳 MCP 的只读工具
   （`query-meals` / `list-nutrition-foods` / `available-coupons` / `campaign-calendar` /
   `mall-points-products` / `now-time-info`），不是大模型编的。
2. **答案是可验证的**：每道题的参考答案由 `Decimal` 精确算出，作答后再调用 MCP 的
   `calculate-price` 做一次真实复核；只有接口真的返回了金额且与预期一致，
   结果才会被标记为 `verify_source = "mcp"`，否则如实降级标注 `"local"`。
3. **没有令牌也能完整跑通**：`MCP → 本地缓存 → 示例快照` 三级降级，评委 clone 下来直接运行，
   界面与命令行会明确告诉你当前是「实时数据 / 本地缓存 / 示例数据」。
4. **只读，绝对不下单**：代码里有 `READONLY_WHITELIST` 常量，白名单外的工具名直接抛
   `PermissionError`；`create-order`、`cancel-order`、`draw-lottery` 等写操作在代码层面不可达。
5. **不采集儿童信息**：进度只写本机 SQLite（`runtime/progress.db`），没有姓名、手机号、
   学校、生日等任何字段，也不上传。
6. **故事线可插拔**：5 条故事线 × 9 关 × 9 难 = **405 个关卡位**，共用同一套 9 个数学模板。
   同一知识点在不同故事线下共享数学骨架，题目数据取自麦当劳 MCP 实时菜单，题面随数据与难度变化；
   新增/下线一条线只需改 `data/storylines/index.json` 里的 `available`，不需要动任何数学代码。

7. **闯关有奖励，但只奖励专注**：一次挑战抽 1~3 题、按用时评金银铜三档，通关收角色卡；
   **干净通关**（不看提示、不答错、不跳过）才解锁那段角色介绍。70 名角色、5 条故事线顺序解锁，
   规则参数外置成 `data/run_rules.json`，命令行与演示页判出来的品阶完全一致。

## 二、它解决什么问题

小学数学应用题最大的痛点是「数字假、情境空」：

- 教材题里的「小明买了 3 个苹果」和孩子的生活没有连接，读完不知道在算什么；
- 家长想加练，只能自己编题，编出来的数字经常不真实、单位不统一、答案自己都算错；
- 大模型出的题，答案对不对没人校验，孩子做错了也不知道是「思路错」还是「题目错」。

「麦麦取经录」把题目锚定在**真实、可核验的数据**上：价格是今天的价格，热量是官方营养表的热量，
券的门槛是真的门槛。于是——

- 孩子算出来的数，可以拿去和真实结算金额对照，**做对了有确定感**；
- 家长不需要自己编题，也不需要自己算答案；
- 每道题都带三级递进提示和分步讲解，错题自动归到 4 类错因（运算错误 / 数量关系错误 /
  单位换算错误 / 漏用条件）。

## 四、5 条故事线（每条九关八十一难）

同一套 9 个数学模板，换一条故事线只是换**关名、角色与题面文案**——数学逻辑一行都不改。
故事线在 `data/storylines/index.json` 里注册，`available: false` 的线**不上线**：
CLI 的 `stages` / `stories` 不列出、演示页不显示、出题也不会注册。加一条线只需要再加一份同构 JSON。

| 故事线 id | 名称 | 一句话 | 取材来源 |
| --- | --- | --- | --- |
| `xiyou`（默认） | 西游记 | 八十一难取真经 | 《西游记》原著（公有领域） |
| `sanguo` | 三国演义 | 群雄逐鹿，借箭分兵 | 《三国演义》原著（公有领域） |
| `silu` | 丝路商队 | 驼铃西去，账目分明 | 古代丝绸之路商旅常识（长安、敦煌、疏勒、撒马尔罕等古地名） |
| `zhenghe` | 郑和下西洋 | 宝船远航，补给有数 | 郑和下西洋的史料记载（历史事实） |
| `shuihu` | 水浒传 | 聚义分粮，账目公平 | 《水浒传》原著（公有领域） |

**九关的数学骨架五条线完全一致**（这正是模板能复用的原因）：

| 关卡 | 主知识点 | 年级 | 真实数据场景 | 数学任务 |
| --- | --- | --- | --- | --- |
| 1 | 万以内加减法 | 3 | 餐品营养表（能量 kcal） | 几样餐品热量合并 |
| 2 | 多步连减 | 3 | 餐品营养表（能量 kcal） | 从预算里连减若干项 |
| 3 | 乘法与倍数 | 3-5 | 菜单单价 | 单价 × 份数 |
| 4 | 除法与余数 | 3-5 | 商城积分商品 | 积分能兑换几份、余多少 |
| 5 | 小数与单位换算 | 4-5 | 净含量（克） | 总克数换算成千克 |
| 6 | 时间与行程 | 4-5 | 活动日历（起止日期） | 含首尾算天数，再算总路程 |
| 7 | 分数与百分数 | 5-6 | 营养表（蛋白质 / 总能量） | 蛋白质供能占比 |
| 8 | 统计与平均数 | 4-6 | 菜单价格 | 平均价格 |
| 9 | 折扣与方案比较 | 6 | 麦麦省券（门槛 / 面额） | 实付金额最少是多少 |

每关 9 难，每条线 81 关，五条线合计 405 个关卡位（81 × 5）。
难度沿「数据项更多 / 步骤更多 / 数位更大」三个方向递进。

> **关于「405」的口径**：405 是**关卡位**（story × stage × difficulty），不是 405 道互不相同的题。
> 9 个模板只按「第几关」索引，同一知识点在不同故事线下共享同一套数学骨架。
> 以默认线西游记为例，81 关在固定种子下产出 **81 条不同题面**——第 1/3/5/8 关靠**份数 / 样数档位**
> （2→10 逐级递增）拉开，第 2/4/6 关的题面里写着预算 / 积分 / 每日里程，第 7、9 关再按难度轮换餐品与购物篮；
> 换一次随机种子，取到的餐品也会换一批。这个数字由 `scripts/selfcheck.py` 机器校验，README 写错会直接 FAIL。

**level_id 命名约定**：默认线（西游记）保持历史格式 `1-1` … `9-9`，其他线是
`<story>-<stage>-<difficulty>`（如 `sanguo-3-2`）。因此 `play --level 3-2` 与所有旧示例、
文档断言完全不受影响。

### 4.6 闯关玩法：解锁链 · 随机抽题 · 品阶 · 角色（v2.0 新增）

规则全文在 `docs/SYSTEM_RULES.md`（唯一真相源，改规则先改文档）。这里是给评委看的摘要。

**锁与解锁**

- 每条线第 1 关默认可玩；第 `k` 关要先通关第 `k-1` 关；下一条线要先走完上一条线**全部 9 关**。
- 解锁状态由通关记录**推导**，不额外存状态位，所以不会出现「进度说是解锁了、实际进不去」。
- 锁定关卡仍然显示关名（让孩子知道后面有什么），**只有守关大将的身份保密**。

**一次挑战（run）抽什么**

| 维度 | 规则 |
| --- | --- |
| 场景 | 每关 10 个备选（10 条场景修饰语 × 该关地点），抽 1 个 |
| 题数 | 1~3 题，权重 30% / 40% / 30% |
| 难度档 | 该关 9 个难度档里抽 `k` 个**互不重复**的档位，按难度升序 |
| 守关大将 | 从 5 名守关池里均匀抽 1 名 |

种子形如 `xiyou-3-1730000000000-0421`，原样记进 `stage_runs.seed`；`--seed` 可以指定，
同一个 seed 抽到的场景 / 题数 / 难度 / 守将完全一样，家长质疑「这题怎么来的」时可以精确重放。

**品阶（只看用时，不看对错次数）**

| 品阶 | 条件 | 含义 |
| --- | --- | --- |
| 🥇 黄金 | `ratio ≤ 0.60` | 又快又准 |
| 🥈 白银 | `0.60 < ratio ≤ 1.00` | 稳 |
| 🥉 青铜 | `ratio > 1.00` | 完成就值得记录 |

基准时间按**该题知识点所属年级**取：3 年级 45 秒/题、4 年级 60、5 年级 75、6 年级 90；
单题上限 600 秒（防止挂机刷黄金）。修正项**只降不升**：用过提示 → 上限白银；
答错 3 次及以上 → 上限白银；跳过某题 → 不给品阶、也不收角色卡（但这一关照常记录通关，不会卡住孩子）。

> 品阶只看用时，不看对错次数；用提示最高白银，跳过不计品阶。

**角色与介绍解锁**

- 每条线 14 名：**9 名闯关大将**（1 关 1 名，固定出场、明示姓名，是这一关的引导者）+
  **5 名守关大将**（线性守关池，每次进入随机 1 名，进入时显示「？？？·守关者」，通关后才揭名）。
- 通关即收卡；**干净通关**（不看提示、不答错、不跳过）才解锁介绍，解锁后永久有效、不会回锁。
- **设计取舍（写在明处）**：需求原文「每关另设 5 名守关大将」若按字面实现，是 9 × 5 = 45 名/线、
  全项目 225 名角色，每人配一段介绍会让文案质量直接崩掉。因此改成**每条线一个 5 人守关池**：
  每关进入时仍然是「5 选 1 随机出现一位」，随机性与收集乐趣不变，角色总量降到 5 × 14 = 70 名，
  介绍才敢一条一条写好。70 段介绍各 60~150 字，全部含一个与数学有关的小细节（如「数过石阶一共
  360 级」「一摞十张，数摞比数张快」），并由自检脚本逐条检查字数、数学线索与红线词。

**CLI 用法**

```bash
python scripts/cli.py play --level 3                      # 进入第 3 关（抽题 → 计时 → 结算 → 收卡）
python scripts/cli.py play --story sanguo --stage 3       # 同上，指定故事线
python scripts/cli.py play --level 3-2                    # 旧的单题模式，行为完全不变
python scripts/cli.py characters                          # 角色图鉴（未遇见 / 已收集待解锁 / 已解锁）
python scripts/cli.py characters --story xiyou --unlocked-only
python scripts/cli.py stages --story xiyou                # 9 关的锁定态、最高品阶徽记
python scripts/cli.py stories                             # 5 条线的解锁进度与锁状态
```

未解锁的关卡 `exit=2` 且只给一句友好提示（`第 4 关尚未解锁（需先通关第 3 关）`），不会抛 traceback。
`stages` 会按解锁状态分三档显示：已通关（带星级与最高品阶徽记）、可挑战、`🔒 第 k 关（需先通关第 k-1 关）`。
五条线 45 关全部走完后，`stories` 与演示页的角色图鉴会额外给出一段总结：
角色收集数、金/银/铜各多少关、以及品阶最低的 3 关（建议重玩）。

**演示页**：故事线锁、关卡锁、守关者剪影、10 选 1 的场景文本、逐题计时、结算页（用时 / 基准 /
ratio / 品阶徽记）、角色卡入手、图鉴三状态，进度按 `story` 分桶写进 `localStorage`；
**中途刷新视为作废**（结算前不落盘，所以不会记录半场的品阶）。
题库、规则参数、角色库与固定用例全部由 `export_demo_bank.py` 从 Python 端导出后注入，
禁止手写；规则参数与 CLI 是同一份 `data/run_rules.json`，抽样算法与品阶判定的实现也按同一份规则写。
导出文件里带 135 条固定用例（`bank.vectors`，5 线 × 9 关 × 3 个 seed），**可以用
`journey.draw_run` 在 Python 侧重算复核**，`selfcheck.py` 跑的就是这一层；
演示页 JS 与 Python 抽到的是否逐位一致，是在开发期用 node + DOM 桩（自己搭的最小 DOM 桩，
不开浏览器）手工比对过的，这个比对脚本不随仓库发布，`selfcheck` 也不会执行页面里的 JS。

**工程说明**：README 第七节的 5 段示例输出由 `scripts/selfcheck.py` 机器校验，不靠人肉同步——
它用文档里记录的固定 seed 重跑一遍，与 README 代码块逐行 diff（时间戳归一化），
不一致就打印「README:行号 期望/实际」并以退出码 1 失败。同一次自检还会验证：
每条 `available` 故事线是 9 关 × 9 难、`brief` 线内不重复、`kp_id` 命中知识点图谱；
**用当前代码把演示题库重新导出一遍**，与 `demo/bank.json` 和 `demo/index.html` 的内联题库三方比对（两边一起改错也会被抓到）；
README 里的「405 个关卡位 / 81 关 / 81 条不同题面」与实际出题结果一致；
以及闯关系统的那一批规则断言（解锁链、故事线链、1000 个 seed 的随机覆盖、可复现、品阶五个边界、
收集与介绍解锁、135 条固定用例与 Python 重算结果一致、70 条角色介绍与 50 条场景修饰语的红线词）。
上面这些断言全部跑在 Python 侧；演示页里的 JS 不在 `selfcheck` 的检查范围内（见 4.6 节末尾的说明）。
改了出题模板、CLI 输出、角色文案或故事线数据后跑一次即可。

## 九、数据与隐私说明

- **只读**：仅调用 8 个只读工具；`create-order`、`cancel-order`、`delivery-create-address`、
  `mall-create-order`、`party-order-create`、`draw-lottery`、`auto-bind-coupons`
  被列进 `FORBIDDEN_WRITE_TOOLS`，代码层面直接拒绝。
- **令牌**：只从环境变量 `MCD_MCP_TOKEN` 读取，仓库内不含任何真实凭证；
  `mcp-config.example.json` 里只有 `Bearer ${MCD_MCP_TOKEN}` 占位符。
- **儿童信息**：进度库只有 `level_id / kp_id / 作答 / 是否正确 / 时间`，没有身份信息，不上传。
- **数据时效**：缓存带 `fetched_at`，有效期 24 小时；过期自动重新拉取。
- **示例数据**：`demo/sample_data.json` 是**离线演示用的示例快照**，页面会显式标注
  「示例数据」，实际运行会替换为实时数据。
