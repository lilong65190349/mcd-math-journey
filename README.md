# 麦麦取经录 · mcd-math-journey

```
[ Python 3.13 ]  [ 纯标准库 · 零第三方依赖 ]  [ 只读 MCP · 不下单 ]  [ 无令牌可离线跑 ]  [ MIT ]
```

> **题目里的数字都是真的，答案由麦当劳 MCP 真实计算校验。**
>
> 用麦当劳 MCP 的真实菜单、营养、价格、优惠券数据，给小学 3-6 年级自动生成数学应用题，
> 用《西游记》取经闯关当故事外壳。**故事只是外壳，数学才是主体。**

非麦当劳官方产品，输出仅供参考，餐品信息与价格以麦当劳官方渠道实时结果为准。

---

## 一、项目亮点

1. **数字是真的**：题目里的价格、热量、蛋白质、优惠券门槛，全部来自麦当劳 MCP 的只读工具
   （`query-meals` / `list-nutrition-foods` / `available-coupons` / `campaign-calendar` /
   `mall-points-products` / `now-time-info`），不是大模型编的。
2. **答案是可验证的**：每道题的参考答案由 `Decimal` 精确算出，作答后再调用 MCP 的
   `calculate-price` 做一次真实复核；只有接口真的返回了金额且与预期一致，
   结果才会被标记为 `verify_source = "mcp"`，否则如实降级标注 `"local"`。
3. **没有令牌也能完整跑通**：`MCP → 本地缓存 → 示例快照` 三级降级，评委 clone 下来直接运行，
   界面与命令行会明确告诉你当前是「实时数据 / 本地缓存 / 示例数据」。
4. **只读，绝对不下单**：代码里有 `READONLY_WHITELIST` 常量，白名单外的工具名直接抛
   `PermissionError`；`create-order`、`cancel-order`、`draw-lottery` 等写操作在代码层面不可达。
5. **不采集儿童信息**：进度只写本机 SQLite（`runtime/progress.db`），没有姓名、手机号、
   学校、生日等任何字段，也不上传。

## 二、它解决什么问题

小学数学应用题最大的痛点是「数字假、情境空」：

- 教材题里的「小明买了 3 个苹果」和孩子的生活没有连接，读完不知道在算什么；
- 家长想加练，只能自己编题，编出来的数字经常不真实、单位不统一、答案自己都算错；
- 大模型出的题，答案对不对没人校验，孩子做错了也不知道是「思路错」还是「题目错」。

「麦麦取经录」把题目锚定在**真实、可核验的数据**上：价格是今天的价格，热量是官方营养表的热量，
券的门槛是真的门槛。于是——

- 孩子算出来的数，可以拿去和真实结算金额对照，**做对了有确定感**；
- 家长不需要自己编题，也不需要自己算答案；
- 每道题都带三级递进提示和分步讲解，错题自动归到 4 类错因（运算错误 / 数量关系错误 /
  单位换算错误 / 漏用条件）。

## 三、目标用户

| 角色 | 用法 | 得到的价值 |
| --- | --- | --- |
| 小学 3-6 年级学生 | `play --grade 4 --count 5` 或打开 `demo/index.html` | 闯关式练习，卡住有三级提示，不直接给答案 |
| 家长 | `report` 生成周报、`wrongbook` 看错题 | 知道孩子薄弱的知识点是哪一个，不用自己算答案 |
| 老师 | 按知识点出题 `play --kp g3_mul_basic` | 直接把真实数据场景搬进课堂，题目可复算 |
| 开发者 / 评委 | 读 `MCP_INTEGRATION.md`、跑 `doctor` | 看到 MCP 真实调用链与降级策略 |

## 四、9 关玩法表（九关八十一难）

| 关卡 | 名称 | 主知识点 | 年级 | 真实数据场景 | 数学任务 |
| --- | --- | --- | --- | --- | --- |
| 1 | 五行山下 | 万以内加减法 | 3 | 餐品营养表（能量 kcal） | 几样餐品热量合并 |
| 2 | 三打白骨精 | 多步连减 | 3 | 餐品营养表（能量 kcal） | 从预算里连减若干项 |
| 3 | 八戒买饼 | 乘法与倍数 | 3-5 | 菜单单价 | 单价 × 份数 |
| 4 | 流沙河 | 除法与余数 | 3-5 | 商城积分商品 | 积分能兑换几份、余多少 |
| 5 | 火焰山 | 小数与单位换算 | 4-5 | 净含量（克） | 总克数换算成千克 |
| 6 | 通天河 | 时间与行程 | 4-5 | 活动日历（起止日期） | 含首尾算天数，再算总路程 |
| 7 | 女儿国 | 分数与百分数 | 5-6 | 营养表（蛋白质 / 总能量） | 蛋白质供能占比 |
| 8 | 真假美猴王 | 统计与平均数 | 4-6 | 菜单价格 | 平均价格 |
| 9 | 灵山取经 | 折扣与方案比较 | 6 | 麦麦省券（门槛 / 面额） | 实付金额最少是多少 |

每关 9 难，共 81 关，难度沿「数据项更多 / 步骤更多 / 数位更大」三个方向递进。

> 关卡按取经路线推进，题目难度以知识点年级标注，跨年级出现属有意设计（如第 7 关会用 3 年级分数初步做引子）。
> `play --grade N` 的筛选口径就是「知识点所属年级」，命令行会把年级与所属关分开显示
> （`年级：4 年级（知识点所属）｜所属关：第 8 关 真假美猴王`），筛选与展示完全一致。

## 五、安装

```bash
git clone <本仓库地址> mcd-math-journey
cd mcd-math-journey

# 只要求 Python 3.13，不需要 pip install 任何东西
python --version

# 想接实时数据就设置令牌（不设置也能跑，会降级到示例数据）
export MCD_MCP_TOKEN="你的令牌"        # Windows PowerShell: $env:MCD_MCP_TOKEN="你的令牌"
```

## 六、快速开始

```bash
# 1. 环境自检：令牌有没有、MCP 通不通、缓存/示例数据可用级别
python scripts/cli.py doctor

# 2. 看九关地图
python scripts/cli.py stages

# 3. 玩一关（出题 → 三级提示 → 作答 → 校验 → 讲解）
python scripts/cli.py play --level 3-2

# 4. 一次性抓取全部数据并写缓存
python scripts/data_source.py --fetch

# 5. 双击打开离线演示页（单文件，零外部依赖）
#    demo/index.html

# 6. 校验 README 示例与本版本代码是否一致（文档防漂移）
python scripts/selfcheck.py
```

## 八、项目结构

```text
mcd-math-journey/
├── README.md                     # 本文件
├── CONTEST_DECLARATION.md        # 参赛声明（原创 / 合规 / 信息安全 / 规则遵守）
├── SKILL.md                      # WorkBuddy Skill 描述（能力边界、只读白名单、工作流）
├── MCP_INTEGRATION.md            # 评委重点：MCP 调用链、业务价值、降级与安全设计
├── workbuddy.md                  # 用 WorkBuddy 开发本作品的复盘
├── mcp-config.example.json       # MCP 客户端配置示例（仅环境变量占位符）
├── .gitignore
├── scripts/
│   ├── mcp_client.py             # 纯标准库 MCP 客户端（JSON-RPC 2.0 / SSE）
│   ├── data_source.py            # 三级降级数据层 + CLI（--fetch / --status）
│   ├── problem_gen.py            # 9 个题型模板 + 三级提示
│   ├── verify.py                 # Decimal 校验 + calculate-price 复核 + 错因诊断 + 讲解
│   ├── progress.py               # SQLite 进度与错题本、家长周报
│   ├── cli.py                    # 命令行入口（stages / play / wrongbook / report / doctor）
│   └── selfcheck.py              # 文档防漂移：把 README 示例与当前代码逐行 diff
├── data/
│   ├── curriculum.json           # 25 个知识点（3-6 年级）
│   ├── journey.json              # 9 关 × 9 难 = 81 关
│   └── cache/                    # MCP 结果缓存（gitignore，运行时生成）
├── demo/
│   ├── sample_data.json          # 示例数据快照（12 个餐品）
│   └── index.html                # 单文件离线演示页（内联 CSS/JS/SVG）
└── runtime/                      # progress.db（gitignore，运行时生成）
```

**工程说明**：README 第七节的 5 段示例输出由 `scripts/selfcheck.py` 机器校验，不靠人肉同步——
它用文档里记录的固定 seed 重跑一遍，与 README 代码块逐行 diff（时间戳归一化），
不一致就打印「README:行号 期望/实际」并以退出码 1 失败。改了出题模板或 CLI 输出后跑一次即可。

## 九、数据与隐私说明

- **只读**：仅调用 8 个只读工具；`create-order`、`cancel-order`、`delivery-create-address`、
  `mall-create-order`、`party-order-create`、`draw-lottery`、`auto-bind-coupons`
  被列进 `FORBIDDEN_WRITE_TOOLS`，代码层面直接拒绝。
- **令牌**：只从环境变量 `MCD_MCP_TOKEN` 读取，仓库内不含任何真实凭证；
  `mcp-config.example.json` 里只有 `Bearer ${MCD_MCP_TOKEN}` 占位符。
- **儿童信息**：进度库只有 `level_id / kp_id / 作答 / 是否正确 / 时间`，没有身份信息，不上传。
- **数据时效**：缓存带 `fetched_at`，有效期 24 小时；过期自动重新拉取。
- **示例数据**：`demo/sample_data.json` 是**离线演示用的示例快照**，页面会显式标注
  「示例数据」，实际运行会替换为实时数据。
